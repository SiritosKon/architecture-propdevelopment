# Task 3. Требования к внешним интеграциям

Единые требования (политика) для интеграций с внешними партнёрскими API. 
Реализуются на уровне API Gateway и сервиса интеграции (см. диаграммы контекста и контейнеров).

| Требование политики внешнего API |
|---|
| Весь внешний трафик проходит только через единый API Gateway; прямые вызовы внутренних сервисов в обход шлюза запрещены |
| Шифрование трафика TLS 1.3 для всех внешних вызовов; чувствительные данные шифруются при хранении (AES-256) |
| Минимизация данных: передаётся только необходимый минимум; спецкатегории ПДн не хранятся на своей стороне без необходимости |
| Мультитенант-изоляция: каждый запрос жёстко привязан к тенанту; кросс-доступ к чужим данным запрещён |
| Контракты API проходят ревью безопасности и версионируются; запрет избыточных ПДн в контрактах |
| Rate limiting, WAF и allowlist IP на шлюзе; защита от перебора и злоупотреблений |
| Управление согласиями субъектов на обработку ПДн (152-ФЗ), с возможностью отзыва |
| Журналирование и мониторинг всех вызовов и событий; алерты на аномалии |
| Взаимный TLS (mTLS) между системами — двусторонняя проверка сертификатов |
| OAuth 2.0 Client Credentials для сервисных вызовов; токены с ограниченным TTL и scope |
| Подпись входящих webhook (HMAC) и защита от replay (timestamp/nonce) |
| Авторизация партнёра ограничена его scope и тенантом (наименьшие привилегии) |
| Единая точка интеграции: API Gateway + сервис интеграции; партнёр не подключается к внутренним сервисам напрямую |
| Синхронные вызовы через шлюз с идемпотентностью, таймаутами и circuit breaker |
| Асинхронные события через webhook или очередь сообщений |
| Отказоустойчивость: недоступность партнёра не роняет внутренние сервисы |
| Сквозная наблюдаемость: логи, метрики и трассировка вызовов через шлюз |
| SLA по безопасности с партнёром и право на аудит интеграции |

## Изменения в ландшафте

На обновлённой диаграмме контейнеров добавлены два элемента:
- **partner-integration-app** — сервис интеграции с партнёрами: маппинг клиентов и собственников, отдаёт партнёру только необходимый минимум данных;
- **API Gateway** — единая точка общения с партнёром (mTLS, OAuth2).
