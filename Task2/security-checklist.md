# Проверочный лист безопасности бизнес-систем PropDevelopment

| Проверяемый пункт | Ответ | Комментарий | Причина включения |
|---|:---:|---|---|
| Проверяются ли права на уровне объекта (клиент видит только свои данные)? | Нет | В ЛК видно ФИО другого клиента — доступ к чужим данным по прямой ссылке на объект (IDOR/BOLA) | Включён как высший приоритет: объектная авторизация — единственное, что защищает ПДн клиентов друг от друга, и проблема уже проявилась |
| Изолированы ли данные разных управляющих компаний (мультитенантность)? | Нет | Партнёр одной УК видит данные другой | Включён из-за B2B-модели PropDevelopment: изоляция управляющих компаний критична, одна утечка между УК подрывает доверие всех клиентов |
| Централизовано ли управление идентификацией (единый IdM)? | Нет | Несколько несогласованных точек регистрации | Включён потому, что без единой идентификации нельзя понять, кто и к каким данным имеет доступ |
| Реализована ли ролевая модель доступа (RBAC, минимальные привилегии)? | Нет | Для Kubernetes завести ролевую модель — Task 4 | Включён как базовое требование разграничения доступа сотрудников и сервисов в кластере (реализуется в Task 4) |
| Применяется ли многофакторная аутентификация (MFA)? | Нет данных | Для привилегированного и внешнего доступа | Включён потому, что MFA повышает защищённость доступа к данным и снижает риск взлома учётных записей |
| Есть ли требования к сложности и обновлению паролей? | Нет данных | — | Включён как обязательный базовый контроль аутентификации для любой системы, работающей с ПДн |
| Проводится ли аудит привилегированных учёток и деактивация уволенных? | Нет данных | — | Включён потому, что контроль жизненного цикла учёток закрывает доступ уволенных и «забытых» аккаунтов |
| Реализована ли защита мобильного приложения собственников как внешнего канала доступа (аутентификация, сессии, защита устройства)? | Нет данных | Внешний канал, управляет умным домом и замком квартиры — отдельная поверхность атаки, защита в кейсе не описана | Включён потому, что это внешний канал, управляющий замком квартиры и умным домом — риск выходит на физическую безопасность жильцов |
| Есть ли политика классификации данных, соответствует ли 152-ФЗ? | Частично | Классификация — Task 1, в системах не закреплена | Включён потому, что классификация — основа всех мер по ПДн и соответствия 152-ФЗ (см. Task 1) |
| Минимизируется ли объём ПДн в формах и контрактах API? | Нет | Контракты API отдают избыточные ПДн | Включён потому, что минимизация ПДн уменьшает объём и последствия любой утечки — приоритет для системы с массой персональных данных |
| Контролируется ли передача ПДн третьим лицам (партнёры, госорганы)? | Нет | Передача без реестра и оснований | Включён потому, что передача ПДн вовне напрямую регулируется 152-ФЗ, а без контроля это юридический риск для компании |
| Выполняется ли резервное копирование всех БД? | Да | «Для всех баз данных выполняется резервное копирование на глубину, необходимую для восстановления» | Включён как базовое требование к сохранности данных и отказоустойчивости бизнес-систем |
| Зашифрованы ли резервные копии? | Нет данных | В кейсе про шифрование копий не сказано | Включён потому, что копии наследуют чувствительность исходных данных и являются отдельным вектором утечки |
| Есть ли межсетевой экран (firewall) для внешнего доступа? | Да | «Доступ для внешних пользователей осуществляется через межсетевой экран» | Включён потому, что внешний периметр — первая линия обороны и его наличие обязательно к проверке |
| Сегментирована ли внутренняя сеть на зоны? | Нет | Сегментацию внутри кластера настраиваем в Task 5 | Включён потому, что сегментация ограничивает горизонтальное перемещение атакующего внутри кластера (реализуется в Task 5) |
| Изолирован ли трафик партнёрских интеграций? | Нет | Единых политик для партнёров нет | Включён потому, что партнёры — внешние субъекты, и изоляция их трафика ограничивает радиус компрометации |
| Информируется ли специалист по ИБ обо всех значимых изменениях? | Нет | Обмен информацией между командами нарушен | Включён потому, что без процесса информирования ИБ технические меры не поддерживаются, а нарушение обмена уже зафиксировано |
| Хранятся ли ПДн граждан РФ на территории РФ (локализация)? | Нет | Часть мощностей арендуется у облачного провайдера | Включён потому, что локализация ПДн граждан РФ — прямое требование 152-ФЗ, критичное при аренде облачных мощностей |
