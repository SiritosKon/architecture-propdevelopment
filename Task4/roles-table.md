# Task 4. Ролевой доступ к Kubernetes (RBAC)

Разграничение доступа построено по организационной структуре компании: каждому домену соответствует свой namespace (`sales`, `gku`, `finance`, `data`).

| Роль  | Права роли | Группы пользователей |
| --- | --- | --- |
| cluster-admin | Полный доступ ко всем ресурсам кластера, включая секреты и RBAC (привилегированная) | platform-admins — DevOps-инженеры платформы |
| security-auditor | Просмотр всех ресурсов кластера и чтение секретов, без прав на изменение (привилегированная) | security — специалист по ИБ |
| domain-editor | Создание, изменение и удаление рабочих нагрузок в пределах своего namespace (настройка кластера), **без доступа к секретам** | доменные *-developers (например, sales-developers) — разработчики и инженеры эксплуатации домена |
| view | Только просмотр ресурсов, без секретов | viewers — владельцы продукта, бизнес-аналитики, менеджеры |

## Скрипты
- `create-users.sh` — создание пользователей (клиентские сертификаты и контексты kubeconfig).
- `create-roles.sh` — создание namespace и ролей (встроенные + кастомная `security-auditor`).
- `create-bindings.sh` — привязка групп пользователей к ролям.
